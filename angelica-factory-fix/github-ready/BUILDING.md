# Building

## Tested method: patch the official release

The public scripts build the same HBM build-3 changes as the tested personal JAR. They do not install anything into Minecraft.

Requirements:

- Windows PowerShell 5.1+ or PowerShell 7.
- A **JDK 8**, including `java` and `javac`. Set `JAVA_HOME` or pass `-JdkHome`.
- An **MCP-named Forge 1.7.10 development JAR** for Forge 10.13.4.1614. This is the `forgeSrc-1.7.10-10.13.4.1614-1.7.10.jar` generated by a ForgeGradle 1.2 development setup (`setupDecompWorkspace`), not the universal installer JAR. Obtain the development tools from [Minecraft Forge](https://files.minecraftforge.net/net/minecraftforge/forge/index_1.7.10.html). Supply your own path with `-ForgeDevJar`; Minecraft development binaries are not redistributed here.
- Internet access on the first build, or the three dependencies listed in [hbm-patch/dependencies.json](hbm-patch/dependencies.json) already placed in `.deps/`.

From this repository's root:

```powershell
.\build.ps1 -JdkHome 'C:\path\to\jdk8' -ForgeDevJar 'C:\path\to\forgeSrc-1.7.10-10.13.4.1614-1.7.10.jar'
```

The script downloads the official Angelica release, ASM 5.0.3, and fastutil 8.5.18, checks their SHA-256 hashes, compiles the two changed helper classes, applies the overlay, and runs the fixture and bytecode checks. It deliberately rejects a different original Angelica JAR. Output:

```text
build/angelica-2.2.36-personal-hbm3.jar
```

Use `-Offline` to require existing dependencies. Use `-DependencyDirectory` to point at another dependency cache. Build output contains no Minecraft test fixtures. Tests can be rerun without the Forge development JAR:

```powershell
.\test.ps1 -JdkHome 'C:\path\to\jdk8' -Offline
```

The tests check the SRG-remapped compiled code against small, independently written fixtures, verify the injected method's stack flow, and compare all archive entries. They are not an in-game reproduction of the original flicker.

The renderer is patched at one expected call site; no full renderer recompilation is done. The equivalent source edit is included in `src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/CeleritasWorldRenderer.java`. The full upstream source is included so reviewers can inspect the surrounding code and license notices.

## Full upstream Gradle build

The upstream Gradle wrapper and source build are retained. They use **Gradle 9.4** and the modern GTNH Java toolchain, unlike the Java 8 overlay process above. For the 2.2.36 checkout, use a JDK 25 build environment and follow [the upstream build documentation](README.upstream.md#building).

```powershell
$env:VERSION = '2.2.36-personal-hbm3'
.\gradlew.bat build
.\gradlew.bat test
```

On Linux/macOS, use `VERSION=2.2.36-personal-hbm3 bash gradlew build` and `bash gradlew test`. Using `bash` also works when a Windows upload has not preserved the executable bit on `gradlew`.

**A full Gradle rebuild has not been verified for this patch.** It may produce a different artifact than the tested binary overlay. Publishing to the original project's Maven, CurseForge, or Modrinth targets is disabled in this copy. No upstream release workflow is included.
